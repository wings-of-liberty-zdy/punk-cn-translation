PUNK 试玩版汉化补丁

为什么 · 3 条原话 这个项目的目的是想要给steam游戏punk做中文 就是punk playtest,这个游戏现在只有试玩版,没有正式版 如果在游戏菜单里面加上语言切换很麻烦,那么就先做简单的,后续再加装

装上插件后，游戏里的文本显示中文，游戏原有文件不改变。

未改动 指内容不变。新增三个顶级项，都能整目录删除。

只拦 TMP 文本的 setter。游戏逻辑读到的还是英文。

为什么只拦 setter 游戏代码用 text 做判断或比较时，拿到的仍是英文。译文不会改变游戏行为。

TextPatcher.cs:24 · set_text 的 Prefix

资源里序列化的 606 处文本不走 set_text，所以要额外扫一遍。

为什么两条路都要盖 606 处 TMP 文本序列化在资源里，反序列化时不经过 set_text。物品名与描述由 ScriptableObject 数据在运行时赋给 TMP，才经过 set_text。只做一条会漏掉另一半。

文本在哪一步被替换？

插件挂不上时，游戏照常启动，只是没有中文。

已知风险 游戏用的是 Unity 6000.3.4f1，对新版 BepInEx 的兼容性没有把握。这条兜底必须先验证。

插件宿主怎么选？

插件按「英文原文 → 中文」查表替换。查不到就显示英文。

半角标点有额外好处 主要 UI 字体 8-bit-hud SDF 的字形覆盖正好是 U+0020–007E，半角标点一定有字形，不会掉字。 查不到的后果 回退显示英文原文。不填空字符串，不写 [MISSING] 这类标记。显示英文能被接受，显示占位符会被当成 bug。

每条文本有一个分配后永不改变的编号。

编号提高的不是匹配率 游戏改了英文，运行时照样查不到、照样回退英文。编号的价值在人工这一侧：旧译文不会丢，它挂在原编号上，可以拿来改成新译文。

翻译表用什么做键？

中文用像素字体显示。像素字体缺字时，那个字回退到黑体。

这张图是示意 字体与布局还没跑进游戏。真实 A/B 截图在字体方案落地后补。

游戏自带的 5 个字体资产，一个中文字形都没有。

好消息 这个 build 已经在用动态图集（两个动态资产），运行时建中文字体资产这条路在本项目成立。

选中的中文字体在 GB2312 全集里一个都不缺。

采样 36px 即字体原生 12px 的 3 倍。实测字形锐利，与游戏 8-bit HUD 风格一致。

字体在运行时从内嵌的 TTF 生成，不预生成字库图集。

最容易卡住的一步 CreateInstance 不触发 TMP 的 OnEnable，图集空闲矩形与字形查找表都没建。缺了它们 TryAddCharacters 只在 TMP 内部抛空引用，不告诉你缺哪个字段。手工建出来即解决。 为什么动态 中文常用字几千个，预生成图集会让补丁包变大好几倍，而且缺一个就要重做。 实测结果 采样 36px 渲染出来字形锐利，和游戏的 8-bit HUD 风格一致。不需要改 shader 做硬阈值。

一条命令从提取跑到打包。发布前校验会拦下不合格的条目。

五支脚本各做一件事，能单独跑。

你用什么方式校对译文？

评审页能筛出待复核条目，并把改动导出成 TSV 片段。

校验拦七类问题：没译文、缺字、超长、仍是英文、标签与换行错位、原文已变更、全角标点。

超长为什么算问题 中文通常比英文短，但按钮和标题栏是固定宽度。译文比原文长超过 20% 就报警。 标签与换行 原文里有 <color=#D2963D> 这类富文本标签，还有写死的 \n。漏掉一个闭合标签会让整段文字显示成红色，或者把标签原文露出来。换行位置也不能照抄英文。 原文已变更怎么处理 编号还在、英文变了，说明游戏改过这一句。校验把它单列出来，译文不会静默失效。

试玩版更新后，重跑同一套命令就产出新补丁。

每次提取的结果按游戏版本号分开存，不覆盖上一版。

建表脚本给新条目分配编号，并把上一版没出现的编号标出来。

共享：文本在哪里，一共有多少。

体量比预想小 8,408 字符，全部译文合起来不到一万字。工作量的大头在字体与注入，不在翻译。 未决风险：商店文案可能来自远程表格 ShopItemsConfig 里存着一个 Google 表格的公开 CSV 地址。如果商店的物品名与描述是运行时从那里拉的，改资源翻不到这部分，本页的范围声明要改。这条正在查。 游戏 LOGO 是图片 Canvas/LOGO 上那张 153×39 的 PNG 就是 PUNK 字样。它是游戏里最显眼的英文，属于"图片文字另算"那一档。 文件 完整报告在 data/inventory.md，逐条清单在 data/strings_raw.json。
